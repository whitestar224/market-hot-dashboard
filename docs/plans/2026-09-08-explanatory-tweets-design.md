# News Trade 解释推文

用户要求：实时弹窗增加“查看解释推文”；后台提前在 X 搜索并精选 3–5 篇，大 V 优先但必须高质量；另开整个屏幕居中的大阅读窗口，默认看 3 篇。

选择独立桌面窗口，而非浏览器内对话框或扩大原通知：不受网页所在位置限制，不占用原播报窗口的生命周期；单列、大字、高对比，额外两篇可展开。

1. 原事件通过现有播报过滤后入队，独立单工作线程预取 X 最近七天相关原帖；先搜长帖/研究/事件梳理，再补全量相关搜索，每次最多 50 条，合并去重保留 60 条，模型输入最多 30 条/32,000 字符。最多 24 个等待任务、256 个缓存。搜索不阻塞告警、没有额外推送。
2. 以主标的、链、CA、本轮催化及证据构成缓存身份，不按币名串用。原帖 ID/作者/时间/链接仅从 X 返回数据生成，AI 无权提供链接。
3. AI 只选编输入帖子，同标的和同事件必须确认。质量≥80、相关性≥85、证据≥65，再考虑关注作者/粉丝数。蓝标不豁免质量。广告、喊单、转推、重复内容和同一作者重复入选排除。宁缺毋滥。
4. 本机只读接口只按缓存 ID 返回已知结果，不接受自由搜索请求。缓存失败/额度/权限/复核不可用时明确提示，不能伪造三篇或增加播报。
5. 阅读器独立进程；只访问固定本机接口，拒绝跳转和外部代理；推文链接严格限制到 X 的具体 status。Esc/关闭始终有效，无自动交易。

验证：纯函数选择门槛、虚构 ID、真假布尔值、作者多样性、缓存并发及持久恢复、搜索失败、原弹窗关联字段、窗口位置和安全链接。真实接口仅做读操作，不发送推文、不签名。

运行验证：125 项 Python 回归、51 项前端回归通过；实际 Tk 控件测试（窗口隐藏运行）验证默认三篇、展开五篇及原文按钮。X recent-search 实际返回 HTTP 200；主模型 API 额度不足，备用通道可完成筛选。4Stock 样例的严格筛选结果为空，未伪造选中三篇。窗口外观尚未做真实桌面截图验收。
