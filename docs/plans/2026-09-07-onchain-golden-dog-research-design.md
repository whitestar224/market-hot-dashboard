# 链上金狗早期研究系统设计

## 目标与验收

在不替换现有“链上投研”生态树的前提下，新增跨链的“今日新币研究池”。系统持续归档当天发现的全部新池，再通过低成本硬过滤、两类量化评分和 AI 终审，把结果压缩为少量真正值得研究的标的。

历史验证把广泛认知的 Meme 龙头和项目型链上龙头分别作为正样本，把它们同期、同链出现的全部新池作为负样本。历史龙头召回率 80% 是最低验收线，目标是在每日候选数和风险误报不失控的条件下继续提高，而不是靠放宽门槛制造虚假高召回。

## 数据流

1. 发现层：按网络分页读取 GeckoTerminal `new_pools`，保存首次发现时间、池创建时间、链、合约和池地址。重复池按“链 + 合约”合并。
2. 补全层：使用 DexScreener 补充价格、流动性、成交、交易笔数和池创建时间。后续可接 OKX WebSocket、EVM 工厂事件和 Solana 程序日志；聚合 API 不是“全量”的唯一证据。
3. 快照层：每次观察只追加时点快照，保留当时可见事实，禁止使用未来字段改写过去评分。
4. 过滤层：先处理无交易、极低流动性、明显卖压、异常数据、池过旧等噪音。安全数据缺失只降低置信度，不直接冒充安全通过。
5. 双评分层：Meme 侧重点为资金扩散、买方广度、交易活跃、叙事传播；项目侧重点为可交易质量、采用、产品/官方证据与持续性。两者独立评分，取更可信的类型进入统一候选池。
6. AI 层：只对规则层幸存者做证据归纳、类型复核、催化与风险解释；AI 不修改原始行情，也不直接替代安全检查。

## 历史回放

共识龙头库为版本化人工标签，记录链、合约、类别、启动时间和纳入理由。回放使用 5 分钟、30 分钟、2 小时、6 小时、24 小时截面，采用按时间滚动的训练/验证切分。主要指标为 Recall@K、Precision@K、每日候选数、发现提前量、风险币误报率和数据覆盖率。缺少启动时点快照的案例标记为“待补数据”，不能计入已通过样本。

## 展示与运行

现有链上投研页面顶部增加研究漏斗和今日精选，原生态树、潜在发行池和预警区保持不变。后台扫描即使页面关闭仍运行；数据库持久化，服务重启只继续增量，不重放旧候选。默认覆盖 Solana、BSC、Base、Ethereum，支持环境变量扩展网络、分页、候选上限和扫描间隔。

## 风险控制

- 新池 API 只覆盖数据商已收录的池，因此界面明确显示来源覆盖，不宣称链级绝对全量。
- 新币最早阶段数据稀疏，低置信候选允许进入短时观察，但不会进入精选。
- AI 不可用时保留量化候选和理由，功能不阻塞。
- 每个评分版本写入快照，参数调整不得回写历史结果。
