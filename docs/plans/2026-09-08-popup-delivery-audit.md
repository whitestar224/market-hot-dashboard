# 实时弹窗漏报审计

日期：2026-09-08。范围：触发、上游去重、桌面去重、队列、启动、显示、覆盖和时效。此审计为诊断，尚未实施下述投递机制重构。所有故障注入都使用假进程、隔离内存与模拟写入，没有发送测试弹窗、交易或改动线上去重记录。

## 核心结论

系统将“检测过/排队过”过早写成不可重复处理，却没有“窗口已经显示”的可靠回执与可恢复待投递队列。多处异常会造成首次机会被消耗。进程启动不等于显示，更不等于阅读。

## 已复现的问题

1. **启动失败后被去重阻止重试**：`launch_desktop_alert` 在入队时写 `DESKTOP_ALERT_SEEN` 与持久化 JSON；worker 启动失败只记录 failed，不撤销已处理标识，也没有重试任务。再次调用同 key 返回 deduped。
2. **重启丢队列**：去重是持久化的，`DESKTOP_ALERT_QUEUE` 却仅是内存 deque。模拟丢失队列并保留 seen 后，同一待投递事件不能恢复。维护重启也具有此风险。
3. **低优先级消息能挤掉高优先级信号**：满 80 条时先 `pop()` 队尾再插入新消息，未比较新旧优先级。隔离复现：队列全是 1000 优先级信号，新普通资讯仍能挤掉一个。
4. **突发信号被节流后按过期抛弃**：关键级默认间隔 6.5 秒、最长队列等待 45 秒。10 条同时进入的隔离复现结果为启动 7 条、过期跳过 3 条。不能简单取消过期检查而晚报旧买点，应调整调度与合并展示。
5. **子进程已失败仍记 dispatched**：模拟 `Popen` 返回一个 `poll()=2` 的已退出进程，worker 仍写入“已调起”。当前无 Map/显示回执；实际绘制异常不能被可靠识别。
6. **同位置覆盖与提前回收**：所有 slot 坐标相同。下层窗口被覆盖时，180 秒自动关闭计时仍继续；第 9 个并发窗口会直接 terminate 最老窗口，不检查显示时长或是否已读。已复现无回执强制关闭。固定左侧位置是用户要求，本身不是问题，缺失的是可见性与未读管理。
7. **上游也过早记 seen**：`sync_site_alert_feed` 在 `launch_desktop_alert` 前保存所有事件 seen。模拟启动调用失败，再轮询同一消息，不会第二次调用投递。即使修好桌面队列，仅修下游仍不足。
8. **通用标题误去重**：不同 X 原文 ID、不同正文、不同事件，但使用相同“某作者转发动态”标题时，仍命中 `alert-global-title`。默认桌面去重窗口最长 90 天，可能误杀真实新内容。明确原文 ID 应优先于通用标题。

复现入口：`tools/audit_popup_delivery.py`。程序输出 true 代表当前缺陷被复现，**不代表修复通过**。

## 代码确认的其他延迟路径

- 除已经拆开的 News Trade 外，多数新闻、榜单、X、补涨来源仍在同一个轮询循环中串行运行。配置 2 秒/12 秒间隔不是实际端到端延迟上限；单个慢源可拖慢后面的来源。
- 前高状态在实际投递前就递增 episode 并落库，持续处于突破区间不会再次生成相同 crossing。此去重对价格状态是合理的，但必须有单独的待投递 outbox，否则不能补偿投递失败。
- 语音历史日志存在 GBK/emoji 编码异常，前一轮已修 UTF-8；这不是窗口没显示的直接证据，不将它混作本次 SOPH 的确定原因。

## SOPH 可核对事实与证据边界

- 当日预警 key episode:2 的桌面去重时间：13:03:41；突破 episode:3：13:12:55。
- 当前价格状态仍在突破区间，数据库 `in_breakout=1`，没有再次 crossing，所以不重复触发同一突破。
- 旧状态仅证明提交过排队，无法确认用户确实看到。事件流归档启用较晚，没有这两条当时的窗口回执。
- 审计时归档有 31 条 popup，均为 dispatched，无 failed/skipped；因 dispatched 只是启动记录，不能据此声称没有漏报。

## 修复建议及顺序（待实施）

> 以下为审计时的计划；19:13 已部署后续修复，结果见文末。历史复现不作为当前运行结论。

1. 将信号触发与投递拆成持久化 outbox：同一 ID 幂等接收，但 pending/failed 不当作 displayed；失败采用有时效上限的重试，重启恢复待投递记录。
2. 增加本机受限的窗口显示回执和失败退出检测；明确 queued、spawned、displayed、covered、dismissed、expired，不伪造“已读”。
3. 固定左侧显示位置保持不变，增加未读队列/数量；控制顶层最低可见时长，被遮挡时不算阅读，也不让普通消息强制替换关键提醒。
4. 优先级容量控制：新低优先级消息不挤掉关键提醒；突发同类信号可汇总但保留每个标的与原始触发时间，过期信号只留记录不晚弹。
5. 上游改为“确认接收入可恢复队列后”推进投递游标；按来源隔离调度，设限并发、超时与退避，避免慢源串行拖延。
6. 精确原文 ID/事件 ID/链合约+状态迁移优先，通用标题不能跨独立事件永久去重。保留用户要求的闲聊过滤和同机会去重。
