# 钉钉热门币前高监控机器人设计

## 目标

- 单独运行一个钉钉推送进程，不读取 Discord 配置，也不受 Discord 发送成功或失败影响。
- 直接复用现有价格监控服务已经生成的信号，包括 AICoin 热门币候选、多交易所合约行情回退、最近 7 日前高、3% 预警区、结构确认和预警轮次。
- 钉钉发送成功后独立记录每个币种的已发送轮次；失败时保留待发送状态，并在下一轮重试。

## 架构

钉钉机器人每分钟读取现有 `/api/price-watch` 接口。接口中的 `latestAlertEpisode` 是价格监控引擎生成的预警轮次，机器人仅在该轮次高于自己的发送记录时推送 Markdown 消息。这样行情和信号规则只有一份实现，钉钉与 Discord 又拥有完全分离的发送配置和投递状态。

机器人首次启动时默认把当前轮次记为基线，不补发历史预警，避免刚配置完成就集中发送旧消息。可通过环境变量选择首次启动时发送仍处于预警状态的最新信号。

## 安全与可靠性

- Webhook 和加签密钥只从环境变量或未纳入 Git 的 `.env` 读取。
- 支持钉钉自定义机器人的 HMAC-SHA256 加签。
- 只有钉钉返回业务成功后才更新本地状态；网络错误、限流或业务错误都会按轮询间隔重试。
- 状态文件采用临时文件替换方式保存，避免程序中断造成半写入文件。
- 日志不输出完整 Webhook、访问令牌或加签密钥。

## 验收

- 加签结果、消息内容、首次启动基线、重复轮次过滤、新轮次发送和失败重试均有自动化测试。
- 未配置 Webhook 时程序明确报错退出。
- `--once` 可执行单轮检查，便于本地配置验证和计划任务调用。
