# 监控页统一链上买入

## 状态

2026-09-08：已检查现有实现和聚合服务接口。用户确认默认滑点上限为 **5%**。
已实现用户签名执行链路；未进行任何真实资金交易验证。用户进一步确认：输入 USDT 数量，按实时参考价格换算 SOL / ETH / BNB 或稳定币数量；同链原生币可买时不跨链。稳定币包括 USDG。跨链路线必须经 AI 选择及独立规则复核。

## 当前实现

- `price-watch.js` 已发现 Binance、OKX、MetaMask、Bitget 的 EVM 注入钱包，保留多个连接；Solana 目前只接了 OKX 专属接口，不能宣称其他钱包已支持 Solana 签名。
- News Trade 的按钮调用 `/api/news-trade/prepare`，只生成预演；服务端明确返回 `liveExecution: false`，前端没有交易提交路径。
- 旧预演依赖交易所划转配置，与这次“使用钱包已有余额”不同，不能直接复用为实际扣款逻辑。
- 标的分布于前高、超跌、结构、新币低位、补涨映射、News Trade、群聊、X 和链上投研等模板，需共享交易入口，不能每个模板自行实现签名。

## 用户体验

每个实际代币标的旁显示“买入”；未确认链、唯一合约或缺少可执行市场时显示不可用原因，不根据币名猜合约。NFT、尚未发币的项目及仅有交易所合约的资产不能伪装成可买的链上代币。

点击买入后展示独立弹层，不受监控列表定时刷新影响。优先当前选择的钱包；首次默认 Binance，其次 OKX。金额输入沿用 USDT 计价习惯，但报价必须显示实际扣款币种及金额，不假设 USDC 永远严格等于 1 美元。

流程：

`标的身份核对 → 金额及余额 → 可执行路线比价 → 最低到账量/费用确认 → 钱包授权与签名 → 源链及目标链到账跟踪`

钱包授权/签名是必须保留的动作，不能承诺所有路线只需一次签名。没有路由、缺少燃料费、价格冲击过大或报价过期时中止，不能后台替用户增加投入或放宽滑点。

## 路由设计

- 共享标的身份格式采用命名空间、链 ID、合约；EVM 地址可规范化比较，Solana 地址保留大小写。
- 服务端统一提供网络能力、报价、状态查询适配器；私钥始终不进入服务端。公共钱包地址仅按报价/余额请求所需发送给对应服务商。
- 实际采用 Relay 报价和官方执行 SDK，不自建跨链桥。2026-09-08 本机实测 Relay `/chains` 返回 Robinhood Chain（4663）、BSC（56）、Base（8453）、Ethereum（1）、Solana（792703809）。网络列出不等于每个新币或金额都有成交路线，最终仍以实时报价与安全解码为准。
- 本机 LI.FI `/v1/chains` 目前返回 HTTP 403；记录为不可用，不能声称已完成双聚合比价，也不绕过访问限制。
- 优先级固定：同链原生币 → 同链稳定币 → 跨链稳定币 → 跨链原生币。前一层存在合格报价即不再使用后一层。同一层按最低到账与成本比较；跨链由 AI 在这些合格候选 ID 中选择或拒绝。“最优”仅指本次可用服务、付款链与合格路线范围，不承诺全市场最优。
- AI 只接收数字化匿名路线摘要，不接收钱包地址、私钥、余额、合约调用或外部叙事；不能生成地址、交易数据或放宽限制。API 不可用时沿用本地 Codex 分析降级，但二者都失败、超时、返回未知 ID 或越权字段时停止跨链，不用规则结果冒充 AI。
- 输入 USDT 数量 × USDT 实时美元价格 ÷ 付款币实时美元价格，按精度向下取整为最小单位；不假设各稳定币严格等值。报价扣款美元价值偏差超过 3% 时重报；燃料费另留。当前默认单笔上限 200 USDT（同时受 200 美元限额保护）。
- 同一订单绑定明确的钱包、付款链/币、收款链/合约、收款地址、金额和滑点。任何一项变更都清空旧报价和待签交易。
- 源链原生燃料费、授权交易燃料费及可能的目标链费用须分别检查并预留；不将全部原生币余额用尽。

## 执行与安全

- 5% 是用户确认的滑点上限，不是价格冲击或总费用的豁免额度。后二者需独立展示和风控；报价不得偷偷附加返佣或服务费。
- 使用已验证的官方 SDK 执行器或严格校验的交易适配器；验证 chain ID、付款人、收款人、输入输出合约、金额、交易目标与授权对象。
- 原始交易数据与结构化报价的对应关系必须校验，不能仅因为聚合接口返回就盲签任意 calldata。
- 授权原则上限本笔需要金额，不默认无限授权。账户或网络切换、钱包断连、用户取消均立即停止后续动作。
- 禁止页面刷新、报价重试或服务恢复自动重新提交交易。提交结果不确定时优先查询交易/nonce/请求状态，不能重新花一次钱。
- 存储订单与源链交易哈希，源链确认不等于买入成功。单独展示跨链中、目标链兑换、部分完成、待退款、退款完成和失败状态。
- 身份混淆、蜜罐或明确无法卖出等高风险继续阻止执行。安全数据缺失不得冒充已通过。
- 报价接口限制来源、请求大小、速率和并发；拒绝任意 RPC/回调 URL，交易能力与 AI 内容/系统自优化严格隔离。

## 性能和故障隔离

- 仅点击买入后查余额及报价，不对整页所有标的持续报价；SDK 按需加载，限制后台轮询。
- 使用小规模独立执行池和请求超时，避免交易报价占满行情监控资源；单一服务商不可用不拖垮页面。
- 链配置可缓存，余额和报价不能长期缓存后直接执行。订单跟踪独立持久化，重启只恢复查询，不恢复自动付款。

## 可验证实施步骤

1. 统一标的身份与买入按钮组件，覆盖监控页各子板块；测试错误链/同名币/无地址/NFT。
2. 提取共享钱包与买入弹层，保留原有连接；测试刷新不中断、账户变化失效、取消签名不重试。
3. 接余额、网络能力、真实路由报价与费用比较；测试余额不足、燃料费不足、部分服务商失败、不同 decimals 精确计算。
4. 接官方执行器与订单跟踪；测试过期报价、恶意目标、重复点击、源链已扣款但目标链失败、进程重启。
5. 在不操作用户真实资金的前提下完成接口与模拟钱包验证。主网小额端到端交易由用户明确发起并在钱包确认，未实测前准确标注验证边界。

## 实现边界

- EVM 仅执行协议目录中 depository 的原生币/精确 ERC20 存入函数，逐字节核对金额、币种、退款账户和订单；授权精确限制为本次输入量。不接受任意合约调用、离线签名或 Permit。
- Solana 目前只允许已解码、固定账户角色的 SOL 原生币存入；SPL 稳定币付款指令尚未完整验证，暂不执行，不能宣称所有链上稳定币均已支持。目标币可否兑换仍以报价为准。
- 未有完整合约安全数据时显示显著风险确认，不伪装安全；命中已知高危直接阻断。协议与上游数据仍有信任及跨链风险，AI 和模拟均非审计保证。
- 每笔报价 60 秒内有效，AI 分析消耗这段时间；过慢则要求重新报价。授权、步骤领取和交易哈希独立保存，进程重启不恢复自动发送。
- SDK 为本地按需加载的约 744 KB 文件，不在监控刷新时初始化或请求余额。新增报价池 6 线程、2 个并发请求，付款链最多 16 条。

## 2026-09-08 验证记录

- 新增 Python 测试 17 项通过（含 15 种报价篡改子案例、AI 越权、精度、过期及重启防重）；相关 JavaScript 测试合计 34 项通过。前高及服务守护相关 Python 回归 12 项通过。
- 公开、只读报价：Base ETH / Base USDC / Solana SOL → Robinhood USDG，实际滑点均为 500 bps，均通过完整执行数据校验。未广播。
- 系统真实 AI 接口对匿名模拟跨链候选返回合法 allow 与原候选 ID，用时约 22 秒；没有钱包地址或私钥进入该提示词。
- 运行服务的 capabilities / resolve / liveness 均为 HTTP 200；Index 的链和合约与用户提供的 Robinhood 页面一致。
- 浏览器确认默认 Binance、USDT 输入、禁用未报价确认按钮、监控刷新保留金额；没有请求用户钱包授权。
- 运行依赖审计无 high / critical；uuid 已升到修复版本。仍有 stream-json 与其上游 jayson 两项 moderate 告警；构建元数据确认 stream-json 没有进入浏览器执行包，jayson 只包含 browser client / generateRequest。没有使用不兼容的大版本强制覆盖来隐藏告警，不能据此宣称依赖全面无漏洞。
