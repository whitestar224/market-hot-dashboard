# 公链生态监控设计

## 状态

- 设计日期：2026-08-16
- 状态：已确认
- 页面位置：`price-watch.html` 的“监控”页新增“公链生态”子功能
- 首个样板：Robinhood Chain
- 隔离范围：不修改“龙头起爆策略”支线；不改变微信群聊内存监控的采集方式

## 目标

把一条新公链视为一个会持续长出细分交易市场的“新交易场所”，在同一页面中完成：

1. 自动与半自动发现公链及其生态项目。
2. 覆盖融资/测试网、主网/发币重点、可交易生态三个阶段。
3. 以 L0-L3 市场树展示每个细分市场，并为每个市场维护 Top 5。
4. 让未发币项目进入“潜在发行池”，发币后自动迁移到可交易榜单。
5. 只对高价值变化即时预警，并能回看证据、得分与历史排名。

## 非目标

- V1 不自动下单，不输出“必涨”或确定性投资结论。
- V1 不依赖付费云数据库或付费 AI 才能运行。
- AI 不作为事实来源，只做摘要、去重建议和市场分类建议。
- 不把本功能直接并入“龙头补涨映射”；未来只允许将已验证的公链龙头作为其上游输入。

## 页面结构

在现有监控模式标签中增加“公链生态”。选中后：

- 左侧为公链列表，按“早期观察 / 主网重点 / 可交易生态”分组，支持搜索、刷新和人工新增。
- 右侧顶部为公链概况，显示阶段、链类型、Gas 资产、最新证据、数据新鲜度和来源健康度。
- 中部为 L0-L3 生态市场树，每个市场卡展示 Top 5、Top 1 龙头、得分变化和关键指标。
- 未发币项目独立进入“潜在发行池”，显示发行阶段、证据强度和项目进度。
- 底部为高价值预警时间线和待人工校验区。

宽屏采用约 300px 侧栏加自适应主区；窄屏改为单列，公链列表横向滚动或折叠，市场 Top 5 保持可读。

## 视觉一致性

公链生态必须复用现有 `price-watch.html` 的视觉语言：

- 深色背景、琥珀色主强调、现有绿色/红色涨跌语义。
- 沿用 `--line`、`--muted`、`--amber`、`--ink` 等全局变量。
- 卡片维持 7px 圆角、细边框、紧凑信息密度和现有字号层级。
- 不引入新的主色、全局字体、大圆角、玻璃拟态或夸张渐变。
- 标签、按钮、空状态、加载状态和错误状态复用现有控件比例。
- 桌面端检查左右宽度平衡、卡片对齐、Top 5 列宽和视觉中心；移动端检查滚动、换行及点击区域。

## 市场分类

基础分类来自用户确认的 L0-L3 结构，并允许一条链出现独有市场：

| 层级 | 基础市场 | 示例对象 |
| --- | --- | --- |
| L0 | 公链代币 | Chain Token、Gas Token |
| L1 | 生态协议代币 | DEX、借贷、Perp、LST |
| L1 | 基础设施代币 | Oracle、Bridge、Wallet、RPC |
| L2 | MEME | 社区币、动物币、热点币 |
| L2 | 发射平台 | Fair Launch、Pump、早期发行 |
| L2 | NFT | PFP、艺术、游戏 NFT |
| L2 | GameFi | 链游、游戏资产 |
| L2 | AI / DePIN / RWA | 生态重点叙事代币 |
| L3 | 稳定币市场 | USDC、USDT、原生稳定币 |
| L3 | DEX 流动性 | LP、Pool、聚合交易 |
| L3 | 借贷市场 | Supply、Borrow、收益策略 |
| L3 | 衍生品市场 | Perp、Options、Prediction |
| L3 | 空投/积分市场 | Points、OTC Allocation |
| L3 | 跨链市场 | Bridge Assets、跨链流动性 |
| L3 | 域名/身份 | 域名、身份、SBT |
| L3 | 节点/验证市场 | Node、Validator、Restaking |

动态分类必须保存产生原因、证据和人工确认状态，不能只由模型生成一个市场名称。

## 核心数据模型

V1 使用独立 SQLite 文件保存证据图谱，避免继续扩大账号数据库的耦合。核心实体为：

- `Chain`：公链、阶段、网络标识、官方入口、扫描配置。
- `StageTransition`：阶段变化、前后状态、证据及确认时间。
- `Market`：L0-L3 市场、基础分类或动态分类。
- `Project`：项目主体、官网、代码仓库、当前发行状态。
- `ProjectMarket`：项目和市场的多对多关系及分类置信度。
- `Asset`：代币、合约、交易池、首次交易时间及状态。
- `Evidence`：来源、URL、时间、摘要、原始哈希和可信度。
- `RankingSnapshot`：某个采集周期的得分、排名和指标拆解。
- `AlertEvent`：高价值事件、去重键、严重度、状态和关联证据。
- `SourceHealth`：每个来源最后成功、失败、延迟和降级状态。

人工录入也是一种证据，优先级高于未确认的自动分类，但不能删除历史事实；纠错通过新增关系、失效标记和审计记录完成。

## 生命周期

公链主阶段为：

`early_watch -> mainnet_focus -> tradable_ecosystem`

项目发行状态为：

`potential -> announced -> contract_confirmed -> trading -> paused/invalid`

迁移规则：

1. 未发现可信合约或真实交易池时，项目只参加潜在发行榜。
2. 官方公告使项目进入 `announced`，不能仅凭社交媒体传闻迁移。
3. 合约需要官方或两个独立可信来源确认，进入 `contract_confirmed`。
4. 交易池满足最低流动性和有效交易条件后进入 `trading`，参与市场 Top 5。
5. 同名币、换合约、迁移链和池子异常先进入待校验区，不自动覆盖原资产。

## 证据与数据源

自动数据源采用可替换适配器：

- GeckoTerminal：网络、DEX、池子、交易、OHLCV 与价格发现。
- DEX Screener：交易对、流动性、成交量、交易数、创建时间与项目资料补充。
- DefiLlama：公链与协议 TVL、协议分类及历史变化。
- GitHub：官方仓库活跃、发行版本和更新时间。
- 官方站点、文档、公告与区块浏览器：公链阶段、合约和合作关系的最高优先级证据。

Robinhood Chain 的样板数据以官方文档和公告为准。2026-07-01 的官方公告已说明公共主网启动；官方开发文档给出主网 Chain ID `4663`、RPC 和区块浏览器。因此样板初始阶段可以标记为 `tradable_ecosystem`，但生态项目、市场和排名仍必须由实时扫描重新建立。

## 自动与半自动流程

1. 人工新增一条链时至少填写名称和一个官方来源；RPC、浏览器、GitHub、GeckoTerminal network id 可随后补充。
2. 扫描器并行读取可用来源，原始响应先归一化为证据，不直接改排名。
3. 实体去重器按 chain id、合约地址、官网域名、仓库和别名合并候选。
4. 分类器把项目关联到基础或动态市场；低置信结果进入待校验区。
5. 生命周期引擎根据证据推进阶段；阶段可暂停或失效，但历史不删除。
6. 排名引擎按阶段计算潜在发行榜或可交易 Top 5。
7. 预警引擎比较连续快照，生成去重后的高价值事件。
8. API 返回最后可信快照、数据新鲜度和当前降级信息。

## 排名设计

### 潜在发行榜

- 官方进度：30%
- 生态地位：20%
- 开发活跃：20%
- 融资与合作：15%
- 社区热度：15%

### 可交易 Top 5

- 流动性：25%
- 成交量与交易数：25%
- 用户或 TVL 增长：20%
- 价格强度：15%
- 生态中心度：10%
- 证据可信度：5%

所有分项先归一化到 0-100。缺失指标不当成 0 分，而是在同类可用维度内重新分配权重，并降低总置信度。Top 1 更换至少满足：挑战者领先 5 分、证据可信度达标、连续两个采集周期领先。

## 高价值预警

仅生成以下四类即时预警：

1. 公链阶段升级。
2. 新细分市场出现。
3. Top 1 龙头变化。
4. 流动性、成交量或交易数显著放大。

项目发币或首次形成有效交易只更新项目状态和市场排名，不进入即时提示与语音播报。

每条预警包含稳定去重键、证据、首次发现时间、最近确认时间和冷却期。V1 默认异常阈值为同口径历史中位数的倍数加绝对门槛，阈值存为配置，后续可以按链调整。页面提醒中心始终保留记录；桌面弹窗只消费高置信且未发送过的事件。

## 接口边界

- `GET /api/chain-ecosystem`：读取所有链摘要或指定链的完整生态快照。
- `GET /api/chain-ecosystem?refresh=1`：请求后台刷新并返回最后可信快照；不让长网络请求阻塞页面。
- `POST /api/chain-ecosystem`：人工新增链/项目/证据、纠错、确认分类、确认或忽略预警。
- 读取接口可公开；修改接口要求已登录，避免远程部署时被匿名篡改。

返回数据必须包含 `updatedAt`、`stale`、`sourceHealth` 和 `warnings`，让页面区分“没有数据”和“数据源暂不可用”。

## 降级与错误处理

- 数据源超时：保留最后可信快照，标记来源延迟，不把指标清零。
- 单一来源失败：继续使用其他来源，排名置信度下降。
- 全部来源失败：显示缓存与明确时间戳，禁止生成新排名变化预警。
- 同名代币/冲突合约：隔离到待校验区。
- 异常流动性或刷量：先进入观察状态，达到连续确认条件后才预警。
- SQLite 写入：使用事务和唯一键；刷新失败不得破坏上一个完整快照。
- 手工纠错：保留操作者、时间和原值，允许追溯。

## 验收

1. “公链生态”与原监控页风格、间距、圆角、颜色和响应式行为一致。
2. Robinhood Chain 能显示官方确认阶段、L0-L3 市场树、潜在发行池、Top 5 和证据。
3. 手工新增链、项目或证据后能在下一次刷新中出现。
4. 未发币项目检测到可信合约和有效交易池后自动迁移。
5. Top 1 只有连续两个周期稳定领先才换位。
6. 四类高价值预警能去重，刷新页面不会重复弹出；形成有效交易不会产生提示或播报。
7. 任一外部数据源失败时仍显示最后可信数据和降级状态。
8. 现有价格监控、补涨映射、事件监控和微信群聊内存监控回归通过。
9. 不修改或引用 `dragon-wave*` 和 `industry_chain_dragon_skill/` 中的实现。
