# 监控页买入采用共享聚合路由与用户钱包签名

## Status

Accepted。原生币与稳定币范围、同链优先、5% 滑点、AI 跨链复核、USDT 输入已由用户确认。实现用户签名执行；未做真实资金成交测试。

## Context

用户要求所有监控标的提供输入金额后链上买入的入口，并自动处理跨链。当前 News Trade 只有交易预演，尚无实际提交功能。监控数据包含仅有币名、交易所合约、跨链同名币和无流动性的资产。

## Decision

共享标的解析、余额/报价、签名和订单状态模块。Relay 提供可执行候选；AI 只能选择通过硬校验的跨链候选 ID 或拒绝，不负责签名与任意交易生成。主密钥留在钱包，由用户签名。链 ID 和合约精确绑定，未核实标的不可自动执行。复用既有钱包连接，交易弹层独立于行情刷新。

## Consequences

### Positive

- 多板块行为一致，修复与风控不重复实现。
- 不托管用户私钥，不引入自建桥的资产托管责任。
- 可将同链和跨链报价在相同约束下比较。

### Negative

- 受服务商网络支持、流动性、接口可用性及钱包签名能力限制，不能保证每个监控币都可买。
- 跨链有部分完成、退款及多次签名情形，需要持久化状态和恢复查询。
- 公共钱包地址会在用户发起报价时发送至必要的数据/路由提供商。

## Alternatives Considered

- 仅增加币安/OKX 网页跳转：实现简单，但不满足页面内输入金额、自动处理余额和跨链的要求。
- 自建多链 DEX + 桥执行器：控制空间较大，但增加合约安全与维护成本，当前不采用。
- 聚合 SDK/API：推荐；依然要求校验报价、授权与实际交易，并向用户披露覆盖范围。
